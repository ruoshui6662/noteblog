## 1. 验收结论

## 2. 第一性原理分析

管理面板的真实闭环是：

```text
用户动作 → 认证会话 → API 契约 → 文件系统变更 → 索引刷新 → UI 状态重建
```

任何一环缺失，界面都会出现“按钮看得到但操作无效”。本次目录问题不是 CSS 或 Vue 点击事件问题，而是运行时后端版本与前端契约不一致：前端调用了目录 API，旧二进制没有注册该路由，因此返回 404。前端降级只能保证可读浏览，不能伪造真实目录写入。

文档结构操作还多一个约束：界面显示标题、源文件路径和公共 URL 不是同一个对象。移动/复制必须以源路径为输入，以服务端返回的新路径为事实；删除必须带当前 hash；目录删除默认只允许空目录，避免一次误操作删除整个内容树。

## 3. 已完成的修复

1. 前端增加文档和目录上下文菜单。
2. 服务端增加文档移动、复制、目录移动、空目录删除接口。
3. 所有结构操作复用相对路径和符号链接安全校验。
4. 目标已存在返回冲突，文档 hash 不一致返回版本冲突。
5. 目录移动后同步更新打开标签、当前路径和文档树。
6. 旧后端目录接口返回 404 时，前端根据现有文档路径生成临时可浏览目录，避免管理页面空白。
7. P4 首轮增加 `metadata` 结构化请求和响应；标题、摘要、标签、排序、草稿由后端写回 Front Matter，并保留 `slug` 等未知字段。

## 4. 优化路线

### 立即执行：运行时版本一致性

- 飞牛上拉取最新 `ghcr.io/ruoshui6662/noteblog:edge`，不要继续使用旧 `ui-preview.exe` 或旧容器。
- 启动后检查 `/healthz`、`/readyz`，再登录管理端。
- 登录后检查 `/api/v1/admin/categories` 不再返回 404。
- 在真实 `/data/content` 下创建测试文档，验证移动、复制、删除后的文件路径。

### P3 下一小步：完整路径操作

- 增加独立的“重命名标题”和“重命名文件路径”，避免用户误解。
- 目录移动返回受影响文档数量和变更前后路径。
- 处理移动后公共 URL、搜索索引、面包屑和相邻文档关系。

### P4：属性和发布状态

- [x] 将 Front Matter 解析和写回集中到 Go 后端，前端只提交结构化字段。
- [x] 增加草稿/公开状态、描述、标签和排序字段的统一响应模型。
- [ ] 预览与公共阅读端都使用保存后的服务端渲染结果，并补充发布状态动作。

### P5：可靠性和可观测性

- 增加 API 集成测试和浏览器端到端测试。
- 为 401、404、409、422 和 500 显示不同的可操作提示。
- 在启动日志中输出应用版本和数据目录，避免再次把旧二进制误认为新接口。
- 对外部文件变化、网络中断和保存冲突提供恢复流程。

## 5. 验收命令

```sh
curl -i http://127.0.0.1:8080/healthz
curl -i http://127.0.0.1:8080/readyz
curl -i http://127.0.0.1:8080/api/v1/admin/categories
```

最后一个请求未登录时应返回 401；登录后在最新镜像中应返回 200。若返回 404，说明运行的仍是旧后端，优先更新镜像或容器，而不是修改前端按钮。
