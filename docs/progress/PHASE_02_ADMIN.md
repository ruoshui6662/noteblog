# 阶段进度：M2 管理员身份闭环

日期：2026-09-06。

本阶段先解决“谁可以写入数据”这个前置问题，再实现文档编辑。身份数据与 Markdown 正文分开保存：SQLite 只保存用户、密码哈希和会话，正文仍以文件为事实源。

## 第一性原理决策

- 管理写入必须先有可验证的身份边界；没有登录态时，服务不提供任何管理操作。
- 密码是不可逆凭据，只保存 Argon2id 哈希，数据库中不能出现明文密码。
- 会话令牌只在浏览器 Cookie 中出现，SQLite 只保存 SHA-256 摘要；数据库泄露时不能直接复用令牌。
- 第一次 `POST /api/v1/auth/setup` 是一次性初始化，已有管理员后永久返回冲突，避免部署后被重复覆盖。
- 数据目录是唯一持久化边界，SQLite 位于 `/data/noteblog.db`，与 Compose 的持久化卷一致；根文件系统仍可保持只读。
- 登录、当前会话和退出都在服务端验证，前端不能自行声明“已登录”。

## 已实现

- 新增纯 Go SQLite 存储，启动时自动迁移 `schema_migrations`、`users`、`sessions` 表。
- 使用 Argon2id（64 MiB、3 次迭代、2 线程）保存密码哈希，并使用常量时间比较验证密码。
- 一次性管理员初始化：用户名允许字母、数字、`_`、`.`、`-`，密码字段只要求非空，不设置长度上限或最小长度。
- 新增接口：
  - `POST /api/v1/auth/setup`：首次创建管理员，成功返回 201，重复初始化返回 409。
  - `POST /api/v1/auth/login`：验证凭据并签发 7 天 HttpOnly、SameSite=Lax Cookie。
  - `GET /api/v1/auth/me`：服务端读取当前会话，未登录返回 401。
  - `POST /api/v1/auth/logout`：删除服务端会话并清理 Cookie。
- 请求体限制为 64 KiB；密码和令牌不写入日志。
- `/readyz` 会检查 SQLite 连接；数据库不可用时服务不报告 ready。
- Docker 构建上下文已加入 `auth/`，生产镜像会执行同一套 Go 测试和 vet。
- 新增 `/admin` 管理员页面，支持首次初始化、登录、当前会话和退出登录；直接打开旧的 `/api/v1/auth/setup` 或 `/api/v1/auth/login` 会跳转到该页面。

## 当前边界

- 目前页面完成身份流程，尚未提供文档创建、修改、删除和媒体上传。
- 当前所有非草稿内容仍公开可读；登录不会改变阅读端结果。
- 会话采用固定 7 天有效期，尚未实现主动续期、管理员多用户和权限角色。
- 初始化接口适合首次部署；生产部署时仍应通过反向代理启用 HTTPS。

## 经验与教训

- SQLite 驱动必须选择纯 Go 实现，否则 `CGO_ENABLED=0` 的多架构镜像会在构建阶段失效。
- 只把 Cookie 发给浏览器不够；退出必须删除服务端令牌，才能真正使已复制的令牌失效。
- 会话表保存摘要而不是令牌本身，令牌泄露面因此限定在请求和浏览器 Cookie。
- `/readyz` 只检查目录会掩盖数据库迁移失败；持久化服务必须把关键依赖纳入 readiness。
