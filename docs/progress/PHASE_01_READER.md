# 阶段进度：M1 阅读端第一条闭环

日期：2026-09-06。

本阶段先交付“文件事实源 → 可重建索引 → 统一 Markdown 渲染 → 阅读端真实路由”这一条最小链路。它是后续搜索、权限和管理端的共同基础，不提前引入数据库或在线编辑。

## 第一性原理决策

- Markdown 文件是正文的唯一事实源。索引只是内存缓存，服务启动和请求时都可以从 `/data/content` 重建。
- 文件系统是外部输入，扫描必须确定且不修改源文件；符号链接、非 Markdown 文件和隐藏目录不进入索引。
- 访客结果默认只包含非草稿文档。解析失败的单个文件被排除并记录问题，不能让一篇坏文件拖垮整个阅读端。
- 路径先标准化再查找，拒绝绝对路径、`..`、空字节和非 Markdown 后缀，避免把 URL 变成文件系统越界入口。
- Markdown 只在后端渲染一次，前端展示后端生成的 HTML 和目录，避免前后端各自维护一套语法规则。
- Front Matter 缺失字段只在内存中推导；服务不会为了补全标题或 slug 改写用户文件。

## 已实现

- 扫描 `/data/content` 下的 `.md` 和 `.markdown` 文件。
- 解析 `title`、`description`、`order`、`draft`、`tags`、`slug`。
- 标题回退顺序：Front Matter `title`、第一个一级标题、文件名。
- 生成稳定的分类和文档树，按同层 `order`、标题排序；草稿不进入访客树。
- 使用 Goldmark 统一渲染 CommonMark、GFM、表格、任务列表、删除线和自动链接；默认不启用原始 HTML。
- 返回文档内容哈希、HTML 和标题目录，并将哈希作为 HTTP `ETag`。
- 新增接口：`GET /api/v1/tree`、`GET /api/v1/docs/*path`、`GET /api/v1/search?q=`。
- 搜索复用公开文档索引，按标题、标签、章节标题、描述和正文加权，返回有限结果片段；草稿不会进入搜索。
- 前端已改为读取真实 API，支持 `/docs/...` 刷新、前进后退、树导航、搜索、空状态、错误状态和文章目录。

## 当前边界

- 当前非草稿文档都按公开阅读处理；管理员初始化、会话和访客权限过滤属于后续阶段。
- 当前每次树或文档请求都会重建内存索引，优先保证外部文件修改可见；缓存和文件监听在 M3 再做。
- 当前只读阅读端没有上传、编辑、删除和媒体权限接口。
- 当前搜索是每次请求重建索引的内存搜索，结果上限 20 条；达到规模瓶颈后再评估增量索引或 SQLite FTS5。
- `slug` 已用于阅读路径，但重复 slug 的冲突检测、重定向和媒体 URL 重写尚未实现。

## 经验与教训

- 先确认事实源和失败边界，再写 API。这样可以避免为了前端演示先造一套会被数据库和权限模型替换的数据。
- 目录链接必须使用渲染器实际生成的标题 ID。Goldmark 对纯中文标题的默认 ID 会回退为 `heading`，因此改用同一套自定义 ID 生成器，让 HTML 和目录始终一致。
- 单元测试必须检查空目录、草稿、坏 Front Matter、越界路径和危险 HTML；只测试“能显示一篇文章”会漏掉最危险的输入边界。
- 搜索也属于公开数据出口，不能因为渲染器隐藏了原始 HTML 就把脚本内容放进结果片段；搜索纯文本必须排除被禁用的 HTML 行。
- CI 是当前唯一稳定的 Docker 运行环境，本机没有 Docker；本地验证重点放在可复现的 Go/Vue 构建，容器行为交给 GitHub Actions 实测。
- `.dockerignore` 使用白名单时，新增 Go 包必须同时加入构建上下文；本地 `go test` 不会发现镜像缺少源目录。
